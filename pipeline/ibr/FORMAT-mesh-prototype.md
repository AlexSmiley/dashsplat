# IBR v1 · offline prototype contract

This specifies the private proof bank, not a released viewer scene. The bank is under `$RS/work/ibr/v1/`. The proofs use the existing live-v5 scene for their fused fallback. A publishable scene would place the files below alongside that fallback's map, tiles, drive and rig; the export gate is reported separately.

## Files, coordinates, time

* `ibr.json`: version 1, source interval in drive seconds, depth unit in metres, mesh stride, fallback manifest name and a camera-name-keyed dictionary. Each camera specifies `native`, `image` and `depth` as [width,height], COLMAP `model` and `params`, timing metadata, `rays` and time-ascending `keyframes`. Intrinsics are native pixel units [fx,fy,cx,cy,k1,k2,k3,k4] for these six OPENCV_FISHEYE lenses. Angles are in radians. The supplied rays avoid any need to invert the distortion in the renderer.
* `rays.bin`: exactly 724 × 469 × 3 little-endian float32 values, row-major top-down xyz, unit rays in the physical camera's right/down/forward frame. Entry (i,j) is at normalized sensor UV ((j+.5)/724,(i+.5)/469). An invalid entry is never usable: the validity mask takes precedence. All raster files keep the distorted sensor orientation; **do not rectify the JPEG or flip its v relative to the depth grid**.
* Keyframe: physical frame number `n`, exposure time `t`, arc length `s` along the published drive, `rowPoses`, `groundPlane`, `displayGain`, `hasInstances`, depth provenance, and paths `rgb/z/mask` relative to the bank. The row poses are *already* timed, at normalized row 0 and 1, including calibrated camera offset and rolling readout. Each is [world x,y,z metres, qx,qy,qz,qw] transforming camera coordinates to the viewer's z-up world. At row v, lerp position and normalized-lerp the quaternions on the shorter arc (negate q1 when dot(q0,q1)<0). Do not apply the timing offsets again. Depth windows can use refined camera poses; the exported transforms are evaluated on the causal drive trajectory so the geometry shares the car and fallback coordinate frame.
* `rgb`: 1448×938 JPEG, photometry-corrected RGB **code values**, half native size for front, native for all other cameras. Treat texture samples as unorm display RGB, not sRGB-decoded linear light. `displayGain` further matches road and sky between lenses for display. `z`: 724×469 grayscale 16-bit PNG, **optical z**, centimetres, zero invalid; Euclidean range = 0.01 × code / unitRay.z. It is not inverse depth. `mask`: same dimensions and PNG type, **integer, nearest sampling**; 0 invalid, 1 static other, 2 road, 3 sky, 4 excluded instance surround, ≥8 an instance. For ≥8, local ID = floor((code−8)/3); (code−8)%3 = 0 unknown, 1 parked, 2 moving. Mask IDs are not cross-camera identities. Browser image decoders that silently convert 16-bit grayscale to RGBA8 lose both depth and IDs: use a real PNG16 decoder and R16UI textures, or unpack the uint16 arrays before upload.
* `sky.jpg`: 1024×512 sky-only fallback fit from the bank, east at the centre column, +z at the top. For a world unit direction d: u=.5−atan2(d.y,d.x)/(2π), v=.5−asin(d.z)/π; wrap u, clamp v. The live-v5 panorama/grade remains the independent fused reference.

## Source selection at target time T

Use the actual viewer camera-to-world orientation expressed right/down/forward, centre E, and forward direction F. The proof replays the controller at 30 Hz (including 0.3 s heading look-ahead, damping and speed pull-back) at 1440×900. The box is proof-only. **No fixed temporal delay.** Both earlier and later static observations are legal; this is an offline bank, not a causal live sensor feed.

1. Per camera decimate the time-ordered *static selection knots*: start at frame 0; take the next whenever arc advances ≥2.4 m **or** time advances ≥0.9 s; include the last. Keep those with |s−s(T)|<62 m. With fewer than two knots for that camera, skip it. s(T) in the proof is accumulated XY distance on the drive sampled at 30 Hz. Use all physical frames, not the decimated list, for movers.
2. Coverage proxies: make 9 target rays at horizontal NDC −.87, 0, +.87 and vertical NDC −.65, +.12, +.72 (positive down). In target space a ray is [x·W/(2f), y·H/(2f), 1]; rotate to world, without normalization. For world vertical component dz<−.07, choose axial range clamp((carZ−E.z)/min(−.01,dz),8,80); otherwise 65 m. Project these world points into each source's calibrated midpoint pose. For fisheye projection use θ=atan2(hypot(x,y),z), ρ=θ(1+k1θ²+k2θ⁴+k3θ⁶+k4θ⁸); multiply the unit xy direction by ρ, then fx,fy and add cx,cy. Coverage h is the fraction of the nine with valid calibration projection, z>.2 and in normalized [0,1]².
3. Make four query positions Q=E.xy + offset·normalize(F.xy), with (offset metres, gain)=(0,1),(11,.49),(−9,.37),(24,.24). For each Q, project onto each consecutive pair of source midpoint XY positions A,B: u=clamp(dot(Q−A,B−A)/max(.0001,|B−A|²),0,1). Minimize |Q−lerp(A,B,u)| + 7(1−lerp(hA,hB,u)) + .05|tA−T|. Use its two endpoints with weights w=1−u,u; skip w<.012. Skip a knot with zero coverage and source-forward·target-forward<−.15.
4. For an endpoint j, D=|sourceCentre.xy−E.xy|, q=max(.014, gain × (front?1.3:1) × exp(−D/18) × (.48+.52h)). Keep (Qj=q√w, w) and deduplicate by camera/frame, retaining the greatest Qj. The 0-m offset is the primary viewpoint witness; the other offsets fill disocclusions. A 19 m pull-back on a straight road emerges from E; it is not hard-coded into a playback-time lookup.
5. Per eligible lens also select its single physical keyframe nearest to T if |t−T|≤.35 s and `hasInstances`. Use mask≥8 only, Qj=max(.55,1−|t−T|), w=1. Remove *all* instance pixels and the 3-pixel guard ring from static meshes, even if a noisy motion track says parked. Current-time rendering does not extrapolate a rigid trajectory or recover an instance without supported depth. The packer fills a zero within an instance only from that same instance's median z when ≥12 samples survive and its p85−p15 < max(2 m,.18 median).

## Mesh and passes

1. Mesh each fourth depth row and column starting at 0; append the last row/column if not included. Use the same diagonal TL–BR in every quad. At a vertex, form world unit direction d from its row rotation and original sensor ray, with row origin O. Static/mover world point = O+d·range. For road, the per-keyframe plane [n.xyz,b] satisfies n·X+b=0. When n·d<−.012 and .4<rp=−(n·O+b)/(n·d)<110, use lerp(rp, measuredRange, clamp((rp−35)/35,0,1)) if measuredRange>0, else rp. This is the sharp photographed road; the live-v5 ground is fallback. For sky store d only: target projection rotates it with **zero translation**.
2. Emit a triangle only when all three integer labels match. Sky is valid without z. For 1,2,≥8 require min range>.3, max range<250, and max−min < .30+.14·min metres. Never bridge label boundaries or depth jumps. Reject invalid/guard cells. Use perspective-correct UV interpolation and a per-fragment nearest mask check against the triangle's label; linear sampling for JPEG colour. Static pass discards ≥8; mover pass accepts only ≥8. Clip at positive target camera near z=.12 m (sky has effectively zero near plane).
3. Fragment quality starts at qf=Qj exp(−1.8·|uv−.5|²). For non-sky, let c=dot(normalize(P−E),normalize(P−Omid)); let X=dFdx(uv)·imageSize and Y=dFdy(uv)·imageSize componentwise; m=|det(X,Y)|/max(.001,sqrt(|X|²+|Y|²)). g=smoothstep(.82,.97,c)·smoothstep(.15,.38,m); for road replace those ranges with (.42,.73), (.08,.19). For non-road static label 1 also multiply by 1−smoothstep(14,28,77.2·|baseline perpendicular to source ray|/max(1,|P−E|)); 77.2 is 8% of the 1440×900 proof's focal length. Reject g<.045 or targetZ<1 m; otherwise qf*=g. These are parallax/texture-stretch rejection thresholds, not semantic depth repair.
4. Two raster passes over the selected meshes. First minimize score C=(ln(max(z,.12))−.17 ln(max(qf,.0001))+2.2)/10 via a depth attachment (clear 1, LESS). z is actual target axial depth, or 500 for sky at infinity. Store winner score, category, unbiased z and source tag. No face culling. In pass two let Δ=10(C−Cwinner). Drop Δ>.075, and never blend sky with finite geometry or movers with static. Weight = max(.00001,w) Qj² exp(−2|uv−.5|²) [1−smoothstep(.025,.075,Δ)]. Add (weight·RGB,weight) and normalize. RGB=clamp(JPEG·displayGain,0,1); for sky mix 73% neutral [1.012L,L,.993L] with 27% RGB, L=Rec.709 dot RGB. This cross-fades compatible bracketing frames, but inconsistent depths still produce winner switches.
5. No contribution above 1e−5 means a hole. Draw live-v5's real splats over its road apron first, then direct IBR wherever supported. In holes above world dz=−.012 use the bank panorama mixed back toward the v5 render by its object contribution. In direct sky, feather the photographed sky over the panorama by .68·clamp(distance to non-sky edge in screen pixels/26,0,1), then mix back toward v5 by object contribution. `render.py` uses an exact 2-D distance transform; a GPU distance field or separable approximation can implement that boundary fade. This last fallback restores visibility, not surveyed geometry; its seams are measured in the report. Draw the viewer car separately with depth, never project an old ego vehicle into its place.

## Reproduction on Studio

From `$RS`, set `OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1`. Run `.venv/bin/python -m pipeline.ibr.pack` then `.venv/bin/python -m pipeline.ibr.balance`. Compile the small native binding with `clang++ -std=c++17 -O3 -fobjc-arc -framework Metal -framework Foundation -dynamiclib pipeline/ibr/metal.mm -o work/ibr/metal.dylib`. The proof bank was frozen as `work/ibr/movie-bank.json` for the two films before extra repeater depths arrived; the stills use `work/ibr/v1/ibr.json`. On a fresh dataset omit the frozen copy and movies use the current manifest. `balance.fit(bank,skyfile)` rebuilds the matching panorama from either manifest. Run `pipeline.ibr.proof road`, `exit`, or `stills` as Python modules. `mesh.metal` is the exact reference for the fragment tests. All files are private and local. Nothing here needs a viewer build, service, cloud deploy, or whole-drive job.
