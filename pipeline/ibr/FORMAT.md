# Photographic layers · viewer contract v1

**Entry point:** [ibr.json](http://10.0.50.51:8090/scenes/ibr-v1/ibr.json), on Studio at `$RS/scene/ibr-v1/`. Check `format == "photo-layers" && version == 1`. Content revisions change pixels/records, not this representation. Refetch the manifest on scene load; key image caches by scene URL, relative path and `contentRevision`. All paths in the manifest resolve relative to the directory of **ibr.json**, including atlas paths embedded in mover shards. There are no dependencies on pictures, depth maps or a separate ground scene outside this directory.

**Release status:** revision 3 is live. Revision 4 below is a staged full-drive candidate; its chase-pose skyline handovers have not passed the release check.

**Playback interval:** use `interval` from the manifest. In the revision 4 candidate the photographed sky and horizon cover 0–361.4197 s; the existing donor ground, near cards and movers cover 93–140 s only. Optional `layerIntervals[layer]` is an array of inclusive [start,end] drive-time pairs; an absent key inherits the scene interval. For a mixed scene, the host retains its own ground, objects and lifetimes. Seek from time and pose alone. [Standalone player](layer_player.py) · [mixed-scene player](horizon_proof.py).

## Root records and coordinate systems

| Field | Read as |
|---|---|
| `interval, units, world` | Two absolute drive times in seconds, metres, z-up in the published **live drive** frame. World basis is right-handed. |
| `drive, rig, chase` | Scene-local `drive.json`, `rig.json` and the chase path named by the manifest (`chase-r4.json` in the candidate). The chase file is literal stdout of `bun tools/chase-track.ts <live-v5-dir> 0 361.41970123 30 1440 900`. Its timestamped records give `t,pos,quat`, through the last 30 Hz sample in the interval. Quaternion is xyzw, camera-to-world, Three.js local **−Z forward, +Y up**. Use the live viewer pose for a user orbit, the file for frame-accurate comparison. |
| `ground` | `{map, sourceScene:"road-stitched-v2", bakedMask:true}`. `map.json` and `rsb/index.json` use the existing viewer splat contract. The selected ground PLYs/RSBs are registered, filtered copies; don't transform or filter the original scene again. `map.sky` is a conventional fallback sky for a splats-only viewer. Layered playback uses the selected skies. |
| `bases` | Map from acquisition camera name to time-ordered records. Each record has `t` (drive s), `n` (sensor exposure number), `s` (drive arc length in m), `pose` (mid-readout sensor-to-world), `rowPoses` (top and bottom readout poses), `pano` (zero-based index into panoramas) and `prev,next` (indices **in this lens array**, null at ends). Sensor poses are [x,y,z,qx,qy,qz,qw], **+Z forward, +Y down, +X right**. Rolling-row rectification has already been baked; use mid-row pose only for selection. |
| `panoramas` | One record per spatial knot: `{id,t,origin:[x,y,z],radius,sky,rgb,matte}`. Several lens records can reference the same knot: its world-aligned sky and far surface already fuse the available photographs around that instant. Camera selection picks the **capture positions/times**; no runtime warping of raw camera JPEGs. |
| `skyElevation, backdropElevation` | [min,max] in **degrees**, in revision 4 [−12,82], [−7,27]. Both panoramas cover 360° of azimuth. The shared dawn sky is 1536×400; far RGB/matte are 4096×448. Use decoded dimensions; they aren't schema constants. |
| `cutouts` | Scene-wide canonical static cards. IDs are unique across all lenses. Do **not** bind their textures, geometry or lifetime to the currently winning base. |
| `movers` | Per-lens array of `{first,last,file}` descriptors in order. File is a JSON array of `{t,n,layers:[card,…]}`; empty arrays are actual empty exposures. Shards are about 2 s long. Preload the current and adjacent shard; use frame times, not shard times, to choose the exposure. |

## Source selection: path proximity first, camera direction on turns

Input is playback time T and camera-to-world pose (eye E, unit look direction D). For the chase export, D = rotation(quat) × (0,0,−1). From drive x,y,t form cumulative XY length; linearly interpolate it at T to obtain S. Select independently on each lens path. Clamp to an endpoint rather than extrapolating photographs past the input bank.

1. For each segment i between consecutive records A,B, let e=A.pose.xy, d=B.pose.xy−e. Compute `f=clamp(dot(E.xy−e,d)/max(dot(d,d),1e−6),0,1)`, `L=length(e+f*d−E.xy)`. Minimise `L + .015*abs(A.t−T) + (abs(A.s−S)<55 ? 0 : 1e5)`. On a tie choose the first segment in array order. The small time penalty disambiguates repeated positions; there is no fixed time lag.
2. For this lens's chosen pair compute a = normalize((1−f)·forward(A)+f·forward(B)), where forward = sensor rotation × (0,0,1). Its cost is `J=L+.32*degrees(acos(clamp(dot(a,D),−1,1)))+.025*abs((1−f)*A.t+f*B.t−T)`. Let Jmin be the lowest lens cost.
3. Set h(x)=p²(3−2p) with p=clamp(x,0,1). Lens weight = h(1−(J−Jmin)/4), normalized across lenses. The two knots have weights lensWeight×(1−f) and lensWeight×f. Ignore zero weights; sum duplicate panorama indices **before sampling**. No static object is multiplied by these weights. Warm the next neighbours for a handover.

Revision 3 regression example (indices are not stable across content revisions): at **100.000 s** the winning lens is the left pillar (24.3° axis error; front 52.3°). The knot weights are approximately 0.366 for index 17 and 0.634 for 18. At **112.000 s** front wins; indices 45/46 get 0.697/0.303. Position, direction and smooth inter-lens overlap are all required to reproduce the turn.

## Photometric and texture conventions

JPEGs are display-referred 8-bit RGB, corrected for exposure/shading and referenced to the front photograph's white balance; mattes are scalar 8-bit PNG, 0 transparent through 255 opaque. The proof blends **code values**, not linearized light, and applies no viewer grade. A WebGL parity path uses RGBA8 with no automatic sRGB decode or colour conversion; apply any final viewer grade once, consistently to the layers and ground. PNG matte is never colour-managed. All listed texture coordinates are top-down. Use the half-texel convention below, accounting for whether your loader flips Y. Colour and matte are separate on disk. For parity, form a premultiplied RGBA texture **before bilinear sampling**. Mipmaps should likewise filter premultiplied colours. Clamp card atlas lookups to the declared rectangle, not across atlas shelves.

## Sky and backdrop

Use a world ray r from the eye through a target pixel. Scale is immaterial for sky; for depth comparisons below use an **unnormalized** camera ray with forward component 1. At 1440×900 the proof uses F=450/tan(25°); its CV ray at pixel (x,y) is ((x+.5−720)/F,(y+.5−450)/F,1). Map to world with the Three.js rotation times diag(1,−1,−1).

* **Sky at infinity.** For direction r, u = fract(.5 + atan2(r.y,r.x)/(2π)). Let e = degrees(atan2(r.z,length(r.xy))). v = clamp((emax−e)/(emax−emin),0,1). Bilinear sampling wraps U, clamps V. Sum selected sky RGB by knot weight. The source sphere already has wide lens feathering, radiometric matching, temporal low-frequency smoothing and angular hole extension. Never draw a sensor rectangle or apply a second seam mask.
* **One continuous finite curtain per knot.** Origin C and radius R are in world metres. Its horizontal cross-section is a circle: world point (C.x+R cos θ, C.y+R sin θ, C.z+R tan e). Use a cylinder strip or raycast. For exact parity let b=dot(E.xy−C.xy,r.xy), q=dot(r.xy,r.xy), disc=b²−q·(length²(E.xy−C.xy)−R²). Positive exit intersection z=(−b+sqrt(disc))/q; no sample if disc≤0, q≈0 or z≤0.3. Set P=E+z·r−C. Use the sky azimuth formula on P and e=degrees(atan2(P.z,R)); reject outside backdropElevation. Sample premultiplied curtain RGB A and alpha a with the same wrapped U and top-down V. Matte contains the skyline, horizon fill and measured ground/sky exclusions. It is not a rectangular billboard.
* **Composite adjacent curtains once.** Sum `Cfar=Σw*A, afar=Σw*a, Zfar=Σw*a*z/max(afar,1e−5)`. Where afar>.001 and Zfar<groundDepth+.12 m, over-composite Cfar+(1−afar)·background. Update the working depth to Zfar only where afar>.5. Invalid samples contribute zero (do not renormalize holes). The two times must not draw as independent opaque cylinders. Fullscreen shader with depth textures or an offscreen RGBA + weighted-depth accumulation pass suffices.

## Borrowing the sky and curtain behind a splat scene (revision 4 candidate)

The six existing layer fields and their sampling equations are unchanged. Deduplicate the sky request by **path**, not by panorama ID: every v4 knot references the same measured world-direction texture. This preserves cloud detail and removes sky exposure changes on every base or lens switch. Apply the viewer's colour grade once to the composed image.

The optional `backdropRange` object gives `startM` (nominal minimum source scenery range in metres), `splatFadeM:[near,far]`, `reference:"horizontal-eye-range"` and `bands`. A panorama's optional `rangeStartM` overrides its source eligibility threshold. **Do not use startM as the cylinder radius.** Use `panorama.radius` and `origin` for the physical draw surface; rangeStartM describes the content baked onto it. For mixed playback multiply host splat opacity by `1−smoothstep(near,far,length(splatWorld.xy−hostEye.xy))` before compositing. Render sky at infinity, donor curtain(s), then the sorted host splats with alpha and depth, then the viewer car. Never render the donor PLYs/cards when the corresponding host layers are selected.

If host and donor do not share a reconstruction frame, evaluate both published drive trajectories at playback time T. Convert host eye and look into donor coordinates via `Ed=donorXYZ(T)+Rz(donorYaw(T)−hostYaw(T))*(Eh−hostXYZ(T))` and `Dd=Rz(donorYaw(T)−hostYaw(T))*Dh`; rotate the full camera basis likewise. Interpolate unwrapped yaw and each XYZ by drive time. Use the **donor** arc length for source selection, donor rays for sky/curtain intersections, and host eye/rays for its splats. Both rigid poses retain the same per-pixel axial depth for compositing. This small registration matters: the independent optimised and live trajectories differ by over a metre near 135 s. Use the identity when the reconstruction frame is shared.

## Canonical cut-outs and movers

For each card, `plane=[nx,ny,d]` with unit n, world plane n·XY=d. The horizontal tangent is b=(−ny,nx). `extent=[u0,z0,u1,z1]`, all world metres, z absolute. Quad corners are XY=n*d+b*u with u∈{u0,u1}, Z∈{z0,z1}. `center` is the world midpoint. Quad is **double-sided**. `rect=[left,top,width,height]` in pixels of paired `rgb,matte` atlas files. Left/top vertex (u0,z1) samples pixel centre (left+.5,top+.5); right/bottom (u1,z0) samples (left+width−.5,top+height−.5). Interpolate UV perspectively. Plane normals/extent never change for a static id.

* `id,kind,source`: ID, semantic kind, [camera, exposure n, exposure t]. Static kinds 2 = building/wall, 4 fence, 5 pole, 6 light, 7 sign, 8 vegetation. `anchor` is contact or depth; `contactRange` (number or null) and `depthRange` describe bake evidence, **not** runtime corrections. Accepted visible foot range agrees within 25% of segment median XY range. Otherwise place the rigid base on the ground under the depth-derived position. All static base-line samples at ≤15 cm spacing pass the measured road exclusion. Ground footprint is the base line; a canopy above the road is not a ground footprint.
* Static `birth,death,fade` are drive seconds. Effective opacity multiplier = h((T−birth)/fade)·h((death−T)/fade). `observations,lastSeen` are diagnostics, not visibility gates. Missing segmentation frames are carried by the same canonical card/texture. Death is precomputed after last sighting when the centre stays behind the default chase or over 100 m away, or at clip end. At birth/death fade the card once; don't cross-fade between still images of it. Visible selection: omit if distance from eye >115 m or dot(center−eye,D)<−(u1−u0); frustum clip the quad against near 0.3 m.
* Movers use the nearest physical exposure to T independently for each lens; choose the earlier on an exact tie. Drop if |t−T|>.24 s. Only that frame's cards are eligible, with opacity multiplier 1. Movers, parked and unknown instances all use this path. They have no static lifetime fields. ID = 1,000,000 + cameraIndex×100,000 + producer track ID, with lens order front/left_pillar/right_pillar. Mover kind = 8+3×trackID+motionCode; 0 unknown, 1 parked, 2 confirmed moving. To coalesce overlapping cameras, sort candidates by decreasing atlas rectangle area; discard a candidate if a previously kept candidate from another camera is <2.8 m away horizontally and <1.6 m vertically. The supplied geometry and texture are exposure-specific; don't reuse later mover frames to fill gaps.

## Depth/order and WebGL parity

1. Sky first, then the viewer's untextured hazed apron and the filtered **ground splats only**. For exact reference apron: intersect z=drive.z(T)−.08; fade by 1−h((distanceXYfromCar−160)/20). Its RGB endpoints are [100,111,113] and [150,158,157], mixing with h((distance−30)/100)·(2−h). Ground splats keep existing PLY DC colours, anisotropic shapes and opacity; no projected ground photography. Reference culls ground tile XY AABBs beyond 115 m from the eye.
2. Ground colour uses sorted source-over splatting. Reference also accumulates G (ground opacity) and M (opacity-weighted Euclidean camera range) by the same source-over recurrence: G'=a+(1−a)G, M'=a·range+(1−a)M. If G>.86 use M/(G·length(r)) as axial ground depth; elsewhere use the positive apron intersection, or infinity if no ground ray. A conventional opaque splat depth prepass is possible but will differ at sparse edges. For reference parity use an auxiliary floating-point target.
3. Composite the blended backdrop and its depth, then static cards far-to-near by camera-space centre z, then current movers in the same sort order. For a fragment use its exact plane depth z=(d−n·E.xy)/(n·r.xy), rejecting |n·r.xy|≤.025, z≤.30, or z≥workingDepth+.04 m. Source-over using its premultiplied colour and effective alpha. Only alpha>.5 updates the working depth; lighter edge fragments blend colour without becoming opaque occluders. A depth prepass plus colour pass (or sampled working depth and ping-pong targets) handles this split. Use clip-space depth for hardware writes, not an axial-metre value in nonlinear z-buffer space.
4. Render the opaque viewer car mesh with a normal depth test versus ground, backdrop, static cut-outs and movers. Shadow and route are ordinary viewer overlays. The proof's gray car is a diagnostic box at the drive pose, 4.5×1.85×1.48 m; its mean-face-depth test is not required for the real car. No ego box or route geometry is in the scene.

**GPU feasibility.** Every playback operation is texture sampling, analytic intersection, quad/splat rasterization, alpha blending, sorting or depth testing. A single ordinary alpha pass over a fixed depth attachment does **not** implement the weighted backdrop depth or semi-transparent ground depth; the additional render targets/passes above do. Segmentation, footprint matching, sky exposure fitting, neighbour reprojection, canonical texture selection and verge filtering are baked offline. No optical flow, depth inference, inpainting or cross-frame state is required in WebGL.

The cold-start model fetches each selected panorama, active card atlas and current mover atlas once and retains it for the clip. It charges time-overlapping mover shards (±.24 s lookahead) and the root scene metadata, and loads RSB tiles within 115 m of the camera. This is a reproducible **asset budget**, not measured HTTP throughput, compressed GPU memory or a required sustained network speed. The 47 s full sequence uses **60.91 MB** of photo assets, or **1.30 MB/s**; all-in cold demand is **163.67 MB**, or **3.48 MB/s**.
