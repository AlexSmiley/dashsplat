## Fidelity on the native window

All three settings use **832×480, 81 frames, 10 Hz**: exactly the [released StreetNVS example](https://github.com/StreetNVS/StreetNVS/blob/fd002eafa62589bd84d44f87e4fc8461fcec3354/README.md), not interpolated 24/30 fps. All use seed 42, six calibrated reference photographs, an empty prompt and CFG 1 (no guidance pass). The same opaque mask, backdrop, ego exclusion, frames and tracked features are used throughout. “Noise” is the actual starting flow sigma, not the pre-shift scheduler argument. At sigma <1 the initial target is (1−sigma) × encoded dense video + sigma × noise, with the image anchor and reference prefix held clean. Scale multiplies the published control branch. The tight run uses 8 steps to fit Studio load; its improvement is for the combined setting, not an isolated estimate of a noise or step-count effect.

**What the eye sees.** The dense input already has road texture, a planted verge, recognisable tree trunks, cloud structure, a bike symbol and turn arrows. It also has green/cyan lighting, softness, stray splats and visible backdrop boundaries. Pure-noise generation simplifies the tree silhouettes, wipes the clouds to near white, and turns the right-turn arrow into dashes. Medium restores the background but smears some arrow heads and stretches short lane strokes. Tight keeps the photographed horizon and the turn; the round-one hill, broad fog panels and conspicuous new vehicles are no longer apparent on this window. But it does not add resolvable leaf structure, credible illumination or cleaner pole edges. Some speckle was already in the source; stronger smoothing trades it for blur. The [same-frame native crops](report/details.jpg) show the tight model doing little that the autoencoder did not already do. Minor shifts still matter: high-contrast features occupy a small fraction of an image, so the tiny thresholded colour-change percentage is compatible with visible paint drift.

**Metric interpretation.** Before looking at the candidate videos, paint strokes were selected on the dense render (bike symbol, arrowheads, dashes and dividers). The [anchors](anchors.json) are backprojected with measured z and tracked against each generated frame. Same 13×13 high-pass patch, ±18 px search, correlation threshold .60, depth-agreement test and 3 px criterion as round one. Repeated strokes can yield ambiguous matches; p90 is an accepted-pattern displacement, not proof that individual physical points moved that far. No legible painted word was identified, so no text-retention claim. For tight, 95/138 patches were within 3 px, and 21/54 frames held **all** measured patches. Warp MAE is mean RGB absolute difference on static depth-consistent reprojections, not optical-flow error in holes or sky. The 10 sampled times yield **15,916 depth-agreeing pixels over 59 physical exposures**; same samples and rolling-shutter calibration for all four native comparisons. These are not independent overhead photographs. [Full scores, timings and per-feature breakdown](report/sweep-metrics.json); per-frame/per-exposure files are on Studio under `work/genvideo/round2/eval/`. The sampled full-frame warp residual is **4.54×** the input for tight; this is not a foliage-only measurement.

## What changed in the inputs

The 150 controls cover 110.0–124.9 s. [Exact viewer track](report/chase-track.json), generated by the basebook viewer tool from the Studio stitched-opt-v3 drive (SHA-256 a6b0ef68c3f04abe689a823ac29511602800eada73d949c32083d08ca0943552). 50° vertical FOV. The contract static splats are composited with the v3 proof's 215 m Gaussian rasterizer. RGB under residual transmittance comes from **only** ibr-v1 photographic sky and matted backdrop, parallax sampled in that scene's drive frame after local yaw/translation alignment. No card, mover, ego, dashboard, foreground-photo insertion or generated return-layer composite. The depth control is optical-axis z from alpha-weighted splat range, valid only for opacity ≥0.80 outside the ego footprint. The panorama can support appearance without supporting depth, and residual colour in the unobserved portion is not measurement. [Reference photos](report/references.jpg) · [exposures and geometry](report/references.json) · [coverage by frame](report/coverage.json).

On the tested 81 frames opaque support averages **66.70%**, photo-backed additional appearance **27.33%**, leaving **5.97%** unverified, including **0.73% ego**. Over the full 150 controls those numbers are 69.57%, 24.94%, 5.49% and 0.72%. Every ego sample has zero metric depth; supported z spans 6.96–210.33 m on the full track. The full RGB is supplied at every time, while the separate geometry mask never claims measured support for the photographic horizon. The persisted background can still have seams or include blended photography. This is appearance coverage, not a percentage of the image that is photometrically exact.

References: two front exposures forced closest in horizontal position to the target near the start and middle; four additional exposures selected for frustum overlap, position and look direction, avoiding duplicates. This run selected five distinct front photos and one right pillar exposure. On the bend at 110.0 s the closest front photo is at 107.6 s (4.7 m horizontal separation); on the straighter 114.5 s section the 113.3 s front is within 0.4 m horizontally and about 4.4 m lower. Overlap is frustum-based, not occlusion-verified. Each photo retains its actual pose; they are not assigned the chase pose.

## Cost and diagnosis

| Trial | Accounted inference | Seconds per generated second | Sampled peak Metal / process RSS |
|---|---:|---:|---:|
| Pure, cold spatial controls | 585.5 s | 72.3 | 5,512 / 3,791 MiB |
| Medium, resumed | 724.1 s | 89.4 | 4,471 / 3,319 MiB (final process) |
| Tight, cached spatial controls | **176.2 s** | **21.8** | 4,471 / 3,317 MiB |

Accounted inference excludes aborted work after the last checkpoint, quiet waits, weights downloads and separate autoencoder diagnostic. The cold pure run reached encoded controls at 66.8 s; the tight run reused the input-hashed lossless latent cache, so 176 s is **not** its fresh-input cost. Shared-machine paging repeatedly interrupted medium; progress resumed at steps 1, 2, 17 and 18. Peaks are per successful process, overlap on unified memory and must not be summed. The pure run's system swapout counter rose by 2,708,926 pages during concurrent jobs; attribution is unavailable. The reported 96 GB is not 96 GB of free GPU memory. Once the native window failed the fidelity criterion, generating a second window or installing a 15 s clip would not answer the question. Round-one files remain archived, but its live-v5 manifest and scene copy were removed. The cache was rebuilt and the published old URL returned Live mode with zero clips. No result was installed in stitched-opt-v3.

**Interpretation:** conditioning was a major cause of round-one invention. The remaining ceiling looks like the **checkpoint and its video autoencoder at this resolution**, not just sparse geometry or a lower-than-native frame rate. The no-denoising control beats every diffusion setting on photo, paint and warp error; denoising adds displacement beyond the codec floor. Rough input foliage remains rough when tightly constrained. Waymo-to-Tesla domain shift and the overhead chase angle are plausible contributors, especially in the pure-noise case, but this drive does not isolate either. There was no in-domain matched control or higher-resolution training ablation.

## Alternative model and next bet

[Wan2.1 VACE 1.3B](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B) **also ran on MPS** on the identical 81 times. With 416×240 controls, 12 steps, .45 initial sigma, same seed, and the opaque region supplied as VACE's preserved context (no pixel compositing), it took **41.7 s** / 5.15 s per output second, peaking at 9,240 MiB Metal and 6,182 MiB RSS. Median/p90 drift **0 / 2.24 px** at half resolution, 136/139 accepted; photo MAE **9.01 vs 8.22 input**, warp **2.67 vs 0.80 input**. Clean-looking road, still soft foliage; no evidence of a realism gain. Do not rank its half-sized pixel drift directly against native scores. The native VACE attempt hit the shared-machine 15.55 GiB MPS cap (15.01 allocated, requested another 560 MiB). [Local alternative clip](report/vace.mp4) · [measurements](report/vace-result.json).

**Cosmos-Transfer2.5 is the better next controlled test, not a demonstrated upgrade:** its edge control can anchor paint, measured depth can be masked onto only opaque surfaces, and low-blur RGB can anchor lighting. The [ready-to-run bundle](report/cosmos-110-118.zip) includes those real inputs, a front photograph, two specs and a pinned launcher. [Requirements, licenses and cost](COSMOS.md). The documented runner requires CUDA/NVIDIA, not MPS. A B200 multi-control pilot is budgeted **$4–12** (0.5–1.5 h at $7.99/h); the cheaper single H100 PCIe edge-only estimate is $1.90–5.69. These include assumed setup time, not a quote or an inference result. No rental, paid API or data transfer to a cloud GPU occurred.

## Reproduce

On basebook: `cd viewer && bun tools/chase-track.ts <stitched-opt-v3-dir> 110 124.9 10 832 480 > ../pipeline/genvideo/round2/report/chase-track.json`. On Studio from `$RS`, with round one's isolated environment and the v3 proof rasterizer already installed:

```bash
export OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 PYTORCH_ENABLE_MPS_FALLBACK=1
.venv/bin/python -m pipeline.genvideo.round2.dense
bash pipeline/genvideo/round2/sweep.sh
bash pipeline/genvideo/round2/score.sh pure medium tight codec
.venv/bin/python -m pipeline.genvideo.round2.compare tight
.venv/bin/python -m pipeline.genvideo.round2.cosmos
```

The first run of pure used 512-row query slices and no control cache; the pressure-adapted launcher uses 192-row slices and caches encoded controls. Slicing preserves full keys/values. For VACE, download only the diffusion safetensors, Wan2.1 VAE, config and license at revision `574e6a744642ce3bee319afc31496b88bde8aac4` into `work/genvideo/round2/vace-weights/`; reuse the installed UMT5 encoder. Run `envs/genvideo/bin/python -m pipeline.genvideo.round2.vace`, then `bash pipeline/genvideo/round2/score.sh vace`. `VACE_NATIVE=1` requests native dimensions; under this cap it did not finish. All original window MP4s, inputs, timing records, metrics and checkpoints are retained under `$RS/work/genvideo/round2/`.
